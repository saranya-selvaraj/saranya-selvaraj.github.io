Product Analysis

Airbnb Host Dashboard — Product Case Study

Overview

A product analytics case study: given a problem statement about Airbnb hosts flying blind on pricing decisions, I worked out which metrics would actually help and built a dashboard prototype in Google AI Studio to surface them. No persona work or user journey mapping — the focus was purely on identifying the right metrics and presenting them clearly.

The Challenge

Most Airbnb hosts aren't running a business — hosting is side income, and they set a nightly price that feels about right, then react to whatever lands in the calendar. Airbnb itself sees how the listing performs, how the area is trending, and what comparable places nearby are charging, but almost none of that reaches the host in a usable form. The brief's pain points were specific: hosts can't tell if a quiet week means falling demand or being priced too high; views don't convert to bookings and there's no visibility into where the drop-off happens; weekend, holiday, and event pricing gets set on instinct; and the warning that a listing is slipping shows up late, as an already-empty calendar. The challenge was to work out which metrics would actually help a host act on these decisions.

Approach

I worked from a given problem statement — background, pain points, and the data Airbnb already has available — and turned it into a dashboard focused on the metrics that matter:

  • Reviewed the available data points: bookings, occupancy, nightly rate, listing views and view-to-booking conversion, reviews and ratings, area-wide search demand and seasonality, competitive-set pricing, and cancellations and lead time
  • Mapped each stated pain point to the metric(s) that would actually surface it — for example, pairing the host's own occupancy against area-wide demand to answer "is my price wrong, or is the market just quiet?"
  • Defined a north star metric and a set of supporting metrics to prioritise on the dashboard
  • Designed a dashboard prototype in Google AI Studio to surface those metrics clearly, prioritising what needs attention now
  • Benchmarked against how other host tools present similar data (Booking.com, Vrbo)

Key Artefacts

  • Given problem statement — background, pain points, and available data — used as the analysis brief
  • Metric-to-pain-point mapping matching each host pain point to the data that would actually surface it
  • North star metric definition with supporting input metrics
  • Competitive analysis document (Airbnb vs. Booking.com vs. Vrbo host tools)
  • Dashboard prototype built in Google AI Studio

Outcome / Impact

Delivered a dashboard prototype built in Google AI Studio that maps each of the host's pain points to the metrics that actually explain it — turning "is my price wrong?" from a guess into a comparison against area-wide demand and the competitive set. Demonstrates the ability to take a given problem statement and available data, and work out which metrics genuinely matter to a user rather than defaulting to whatever's easiest to display.

What I Learned

Dashboard design is really prioritisation design — the hardest question isn't "what data do we show?" but "what does this user need to answer right now?" Working from a given problem statement instead of my own research pushed me to be disciplined about mapping each stated pain point to a specific metric, rather than defaulting to whatever data was easiest to display. Defining a north star metric early kept every design decision grounded in measurable host success, not aesthetic preference.
